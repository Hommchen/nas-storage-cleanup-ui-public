# NAS 清理台

本地工具会把 Jellyfin 媒体、qB 任务、私有站保护状态和真实硬链接聚合成一份资源清单。电影一部一行，电视剧一剧一行，同时显示中英文名。

这是一个面向单机 NAS 的安全清理控制台，默认采用失败关闭策略。仓库不包含真实媒体清单、运行缓存、站点 Cookie、tracker、passkey、infohash 或控制令牌；`tests/fixtures/resource-snapshot.sample.json` 只包含虚构示例数据。

Hit and Run（H&R）默认关闭。关闭时 H&R 完全退出清理保护链、状态标签、筛选器和统计；开启后在配置中按“一站一行”填写站点的 H&R 列表入口相对路径，例如 `btschool.club` + `/myhr.php`。站点从 MoviePilot 已配置的登录站点读取 Cookie/UA，路径必须绑定受支持的解析器；后台随资源快照刷新自动测试。首次成功前该站不生效，已成功后查询失败只保护该站任务并提示用户；没有任何有效站点时等同于 H&R 未生效。

名称先使用 Jellyfin / TMDB 身份，再用同一硬链接对应的 qB 发布名互证。只有标题与年份一致时才接受发布名；同剧不同季会按唯一媒体身份合并。缺少明确中文名、同名却对应多个 TMDB 身份或年份冲突的条目统一进入“名称待核”，三档清理全部锁定，不用猜测结果放行。已有明确中文片名但没有独立英文名的条目不再重复标记为名称待核；若存在媒体身份冲突，仍按冲突规则锁定。

少量 MoviePilot 无法识别的发布名可写入 `db/media-name-overrides.json`。该文件只接受经过来源审计的 HTTPS 记录，并按完整发布名和媒体类型精确命中；年份冲突、缺少中文或英文、身份格式错误、重复记录都会失败关闭。映射只补充展示身份，不会覆盖 H&R、未完成下载、硬链接或站点风险保护。

## 正式部署

正式服务完整运行在 NAS 的部署目录（示例为 `/srv/storage-cleanup-ui`），提供两条并行入口：

- 独立页面：局域网浏览器打开 NAS 网关地址的 `:3000` 端口，原页面与交互保持独立。
- MoviePilot 原生页面：登录 MoviePilot 后从侧栏“存储清理”进入；页面位于 MoviePilot 自身域名和登录态下，因此也能通过现有 MoviePilot 公网入口访问。

前端与控制接口只监听 NAS 回环地址，再由同源网关统一开放到局域网地址。控制端口 `8765` 不对局域网单独开放，网关拒绝未授权来源。MoviePilot 容器只能访问 `/control`，且每次请求必须同时携带控制服务启动时轮换的内部令牌；令牌不进入 Vue、浏览器响应、仓库或日志。

当前部署脚本和 systemd 单元按本项目的 PiNAS 拓扑编写。用于其他 NAS 前，应先核对并调整 Pi 用户、局域网地址、Jellyfin/MoviePilot/qB 数据位置、下载根、媒体根和允许删除根；不要直接在未知目录布局上开启执行模式。

部署一个经过完整测试的新版本（先按你的 NAS 修改 systemd 模板中的用户、目录和网关监听地址）：

```bash
/opt/homebrew/bin/python3.12 scripts/deploy-to-pi.py --pi-host nas-user@nas-host --pi-base /srv/storage-cleanup-ui
```

部署器先在独立版本目录安装、测试、构建两套前端并采集真实快照，通过后才原子切换 `current`，旧版本不会被覆盖。随后从 `package.v2.json` 安装或更新本地私有插件 `StorageCleanup`，重载 MoviePilot，并从正在运行的 MoviePilot HTTP 接口回读联邦入口和容器桥接。Pi 上控制、前端和局域网网关三个 systemd 服务均随开机启动；控制服务带确认门禁执行能力，仍须先生成五分钟安全预演、确认私站风险，然后在页面上连续点击两次确认。Mac 不运行任何配套服务。

## 本机开发

默认只读模式：

```bash
npm run local
```

长期使用或验收生产构建：

```bash
npm run local:production
```

确认需要实际操作时，启动带执行能力的模式：

```bash
npm run local:enabled
```

生产构建对应的执行入口：

```bash
npm run local:production:enabled
```

然后打开 `http://localhost:3000/`。开发、生产前端与控制服务都强制监听 `127.0.0.1`，不会向局域网开放。页面启动时优先读取控制服务当前快照；控制服务离线时才退回静态只读副本，不会把构建时旧清单固化进前端包。

## 三档操作

- 停止做种：只停止 qB 任务，保留任务和文件。
- 退出做种：备份 qB 原始种子和恢复状态，再移除 qB 任务，保留全部文件。
- 完整删除：复核 qB 逐文件清单、硬链接、白名单、占用状态和 MoviePilot `mediaserveritem` 索引；先把精确文件原子移入同盘隔离区，qB 退出并删除已校验的 MoviePilot 索引后才释放空间。索引不可读、身份变化或删除后回读失败时会中止并回滚，不会只删文件留下脏媒体库记录。

每次执行都需要：

1. 生成五分钟有效的真实安全预演；
2. 单独确认私有站风险；
3. 在页面上第二次点击确认；执行前系统会再次刷新 NAS 状态；
4. 执行前再次刷新，仅当所选资源的任务和文件指纹不变时继续。

H&R、未完成下载、未知硬链接、越界路径、缺失文件、符号链接或正在使用的文件都会被自动拦截。学校站 H&R 使用官方种子的 infohash 与 qB 精确匹配，但只有文件列表已验证且重检达到 100% 才计为已恢复；只添加官方任务或重检不足不会解除对应任务或资源的删除锁。缺失任务的恢复候选只认官方 `.torrent` 与 qB 完整任务逐文件的“文件名 + 字节大小”清单一致，标题相似度不参与判断。缺失任务若能用官方视频文件大小集合唯一关联到现有媒体，就锁定对应资源；无法关联的记录保留在 H&R 缺口清单中作风险提示，但不再全局锁定无关资源。完整删除仍逐条依据所选资源自身的 H&R、下载状态、硬链接和路径门禁决定。

缺失的学校站任务会用官方种的视频文件字节集合与现有媒体做只读关联；即使 MoviePilot 标题或身份相符，也不能覆盖 payload 结果。只有字节集合唯一对应时，资源行才显示“H&R 缺失”并锁定；这只证明媒体文件仍在，不代表 qB 任务已经恢复。H&R 只有重新加入官方种、100% 重检并回读 qB 状态后才算恢复。

页面会忽略较早返回的并发预演，避免快速切换清理等级或站点确认时显示旧计划。原计划在执行前刷新期间仍继续计时，超过五分钟即拒绝执行；执行或恢复后的清单刷新一旦失败，后续新计划会保持锁定，直到一次完整刷新成功。

每次快照发布和控制服务启动都会重新校验公开/私有清单：schema、快照编号、生成时间、统计、资源 ID、中英文名称锁、H&R 数量和脱敏结果必须闭合，私有库存还必须保持 `0600`。任一检查失败都会保留旧页面并锁定新计划。

如果 qB 删除请求的结果无法回读，文件不会被释放，而是保留在同盘隔离区；qB 原始种子、恢复状态和事务阶段一并保留。退出或删除会在停止 qB 之前记录原运行态；没有 qB 任务的纯媒体删除也会在移动第一个文件前建立完整恢复映射。任何缺少事务状态的遗留备份、隔离内容或非终态事务都会锁定全部新操作，防止在不确定状态上继续清理。

页面会把未完成事务置顶显示，并只提供与 qB 当前状态一致的恢复方向：任务全部仍在时只能回滚，任务全部已退出时只能完成原事务，混合状态不提供自动恢复。H&R 缺口也可在页面查看，但只显示标题与“精确 payload 候选待重检 / 媒体已锁定 / 未定位恢复来源”，不暴露站点 ID、hash 或路径。

未完成事务先只读检查：

```bash
/opt/homebrew/bin/python3.12 scripts/recover-transaction.py plan_xxx
```

检查结果会给出两条逐字确认短语。qB 任务仍在时只能使用 `--action rollback` 恢复原路径与原运行态；qB 任务已退出时只能使用 `--action finalize` 完成原事务。恢复器会再次核对路径白名单、隔离映射、inode、大小、硬链接数和 qB 任务状态，不允许跳过确认。

公开页面和浏览器接口不包含本机路径、tracker、passkey、infohash 或私有 H&R 标题；这些执行数据只保存在权限为 `0600` 的本地私有库存中。

## 跨 NAS 配置

MoviePilot 插件的“设置”页用于填写当前 NAS 的拓扑，不需要修改源码。配置保存在主机侧的 `shared/config.json`（开发环境默认为 `.runtime/config.json`），不会写入浏览器、公开快照或仓库。可配置 qBittorrent 地址、Jellyfin/MoviePilot 数据库、qB 种子备份、事务备份、允许扫描/清理的根目录，以及每个数据卷对应的同盘隔离目录。

同一设置页的 Hit and Run 区域只有一个全局开关和多行站点配置。每行只填写一个站内相对路径；站点下拉选项来自 MoviePilot 当前启用的站点记录。默认预置学校站 `/myhr.php` 作为待验证配置，但总开关保持关闭。后台测试失败只在清理台显示失败提醒，不显示正常轮询状态，也不会把未配置或从未成功验证的站点当作 H&R 保护。

保存配置只执行结构校验和只读路径探测；缺失路径会让资源清单保持过期，路径越界、符号链接或跨文件系统隔离目录会直接拒绝保存。配置变化会清空旧清理计划，必须重新刷新真实清单后才可能生成计划。`config/config.example.json` 是可复制的非敏感模板；启用执行仍需要原有的五分钟预演、私站风险确认和二次确认。

首次部署前，先在 MoviePilot 的插件设置页保存配置并确认“只读探测通过”，再刷新清单。仓库内置的示例值仅用于展示字段格式；未完成配置时清理台会保持锁定，不能直接套用到任何 NAS。

## 开发验收

提交改动前运行：

```bash
npm test
npm audit --json
npm audit --omit=dev --json
npm run smoke:readonly
```

`npm test` 会依次完成前端静态检查、129 项安全与事务测试、MoviePilot Vue 插件测试与联邦构建、类型检查、独立页面生产构建和示例快照渲染测试。两项依赖审计必须同时为零漏洞；生产服务启动后还需在正常桌面窗口复核列表、筛选、选择栏和三个清理预演弹窗。

`smoke:readonly` 只接受 loopback 控制服务，并要求执行模式关闭。它会从外部验证 Origin / 会话门禁、公开与私有快照闭合、H&R 缺口、未完成事务、无效计划拒绝及执行接口失败关闭；不会生成有效计划，也不会触发 NAS 或 qB 写操作。

# Architecture

NAS 清理台把“展示”和“真实执行”刻意分开。浏览器只看到经过脱敏的资源视图；涉及 qBittorrent、媒体文件、MoviePilot 索引和 H&R 的执行状态保留在 NAS 本机。

## 组件边界

### 1. Web UI

独立页面负责资源浏览、筛选、选择、清理等级和安全预演确认。

- 面向浏览器的资源数据必须脱敏；
- 默认只读；
- 不持有 tracker、passkey、infohash、控制令牌或真实本机路径；
- 控制服务不可用时，只允许退回安全的只读视图。

### 2. MoviePilot 插件

`plugins.v2/storagecleanup` 提供 MoviePilot 内的原生入口，使清理台可以在已有 MoviePilot 登录态下使用。

插件是入口层，不应把本机敏感执行数据塞进前端 bundle。

### 3. Control service

控制服务位于浏览器和 NAS 写操作之间，负责：

- 采集/刷新真实资源状态；
- 生成短时有效的清理计划；
- 校验路径边界、硬链接、下载状态、H&R 和事务状态；
- 执行停止做种、退出做种和完整删除；
- 管理事务恢复和隔离区。

真实执行模式必须显式开启，不能因为前端参数或配置缺失而自动放行。

### 4. Resource snapshot

资源快照把 Jellyfin / MoviePilot 媒体身份、qBittorrent 任务和文件关系聚合为统一资源。

项目区分公开视图与本地私有执行库存：

- **公开快照**：允许进入浏览器和测试 fixture，只包含脱敏字段；
- **私有库存**：只留在 NAS 本机，包含执行所需路径、任务身份和恢复信息。

两者必须通过 schema、资源 ID、统计和快照版本闭合校验；校验失败时保留旧状态并锁定新计划。

### 5. Transaction / quarantine

完整删除不直接从最终路径不可逆删除。

文件先移动到同一文件系统上的隔离区，并记录事务阶段、inode、大小、原路径、qB 状态和恢复材料。只有后续校验完成后才释放空间。

存在非终态事务时，新的真实操作默认锁定，直到事务被回滚或完成。

## 数据来源

当前核心数据来源包括：

- Jellyfin 媒体库身份；
- MoviePilot 媒体索引与配置；
- qBittorrent 任务及逐文件清单；
- 文件系统 inode / hard-link / path 状态；
- 可选的私有站 H&R 状态。

任何一个关键证据缺失都不应该被“标题相似”“猜测路径”之类的弱信号替代。

## 三档执行

| 等级 | qBittorrent | 文件系统 | MoviePilot 索引 |
| --- | --- | --- | --- |
| 停止做种 | 停止任务 | 不改动 | 不改动 |
| 退出做种 | 备份并移除任务 | 不改动 | 不改动 |
| 完整删除 | 校验后退出任务 | 先隔离，再释放 | 校验后同步清理 |

## Fail-closed 原则

以下情况应阻止真实操作，而不是继续尝试：

- 资源身份冲突；
- 下载未完成；
- H&R 风险未解除；
- 硬链接关系未知；
- 文件路径越界或为符号链接；
- 文件缺失/重新出现导致指纹变化；
- MoviePilot 索引不可验证；
- 已存在未完成事务；
- 执行前刷新失败。

## 开发约束

涉及删除链路、H&R、硬链接、路径门禁、事务恢复或脱敏逻辑的改动，需要同时增加失败场景测试。

不要为了“兼容更多奇怪目录结构”降低默认门禁。跨 NAS 的差异应优先通过显式配置解决，而不是扩大自动推断范围。

更多协作要求见 [`../CONTRIBUTING.md`](../CONTRIBUTING.md)，安全问题见 [`../SECURITY.md`](../SECURITY.md)。
